System Architecture #10

4. Scale up. 5. Then shard.

4 · scale up
a bigger machine
8 cores, 32 GB
→ 32 cores, 128 GB
  • no code change
  • buys time while you fix the cause
  • cost: money, and there is a biggest machine
5 · shard
split the data
users A–H → db 1
users I–P → db 2 …
  • weeks of work
  • queries across shards get hard
  • cost: complexity you keep forever
Shard: one piece of the data, on its own database. Each shard holds some of the rows. Example: users A–H on database 1, I–P on database 2.
ruleShard only when steps 1 to 4 have truly run out.
