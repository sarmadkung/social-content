Which stack for the backend and data?

API and servicesthe server code
DEFAULTGo + Postgresone small binary, cheap concurrency, low memory, easy to review
PICK SOMETHING ELSE WHEN

a CPU-heavy hot path → Rust for that part; simple CRUD, all-TypeScript team → Node.js

App datausers, orders, settings
DEFAULTPostgrestransactions, joins, JSON and full-text search in one database
PICK SOMETHING ELSE WHEN

a measured pattern Postgres can't serve, like huge key-value → DynamoDB

Analyticsreports and dashboards
DEFAULTClickHouse, or DuckDB for filesreads only the columns a query needs, on every core
PICK SOMETHING ELSE WHEN

a few million rows → a Postgres read replica
